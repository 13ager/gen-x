## Prompt File Conventions

### Naming Convention
- Use underscores for spacing: `The_Pre-Meeting_Oracle`
- Prefix with category number: `1.1_`, `2.3_`, etc.
- Use descriptive, action-oriented names
- No file extensions for prompt files (plain text)

### Content Structure
Each prompt file should include:
1. **Purpose/Context** - When and why to use this prompt
2. **The Prompt** - The actual AI prompt text
3. **Input Variables** - What context/data needs to be provided
4. **Expected Output** - What results to expect
5. **Example Usage** - Real-world application examples

## Writing Style Guidelines

### Tone & Voice
- **Direct and authentic** - No corporate fluff or buzzwords
- **Gen X sensibility** - Practical, skeptical, self-aware
- **Battle-tested** - Real experience over theory
- **No-nonsense** - Results matter, productivity theater doesn't

### Language Principles
- Write in complete sentences (we're the last generation that can)
- Avoid excessive jargon - speak like a human
- Be real about challenges - acknowledge what doesn't work
- Use humor sparingly but authentically
- Reference actual experience, not aspirational BS

### Content Quality Standards
1. **Test everything** - If it doesn't work, it doesn't ship
2. **Provide context** - Explain when and why to use each prompt
3. **Show real results** - Examples from actual use cases
4. **Keep it practical** - Focus on what works in the real world

## Working with Prompts

### Adding New Prompts
1. Determine the appropriate category (1-4)
2. Follow the naming convention
3. Include all required sections
4. Test the prompt thoroughly
5. Add entry to README.md index

### Editing Existing Prompts
- Maintain the original structure
- Preserve the authentic voice
- Document significant changes
- Test before committing
